LIVE EXECUTION / MICROSOFT FOUNDRY

Uruchom agentów na zadaniu

To nie demonstracja ani odtworzenie nagrania. Po wpisaniu kodu GitHub Actions uruchomi rzeczywiste agenty Microsoft Foundry, które od nowa opracują rozwiązanie zadania: bezpieczne kolumny wirtualne w Pythonie oraz ETL pliku sprzedażowego. Kod, testy i wynik będą powstawać w nowym, audytowalnym przebiegu.

01
Data ArchitectCzyta wymagania, sprawdza dane i przygotowuje plan oraz kontrakt kodu.
02
Data Engineer · P3 / P5Pisze pliki Python i testy. Docker uruchamia kod, a błędy wracają do poprawy (maks. 3 próby).
03
Verifier · P4 / P6Pisze własny test i sprawdza błędy. Po zaliczeniu P4 system sam tworzy draft PR; człowiek decyduje dopiero o scaleniu.

GOTOWOŚĆ URUCHOMIENIASprawdzanie połączenia

Po uruchomieniu system wykona Architect → Engineer → testy Docker i ewentualne poprawki (do 3 prób) → Verification Engineer → P4 → automatyczny draft PR i osobne CI. Przebieg zwykle zajmuje kilkanaście minut; przy poprawkach lub kolejce GitHub może potrwać ponad 30 minut. Widzisz aktualny krok i link do wykonania. Limit: 5 startów / 24 h, 1 aktywny.

    01 / ZADANIE

    Zakres dostarczonego rozwiązania

    Funkcja kolumn wirtualnych i pipeline sprzedażowy. W nowym procesie Data Architect projektuje kontrakt, Data Engineer tworzy kod, a Verification Engineer przeprowadza niezależną kontrolę.

    01 — PYTHON APIsolution.py

    Kolumna wirtualna

    Funkcja add_virtual_column(df, role, new_column) tworzy kolumnę na podstawie bezpiecznie ograniczonych działań arytmetycznych. AST waliduje dozwolone nazwy i operatory, bez wykonywania arbitralnego kodu.

    Wynik: funkcja, oryginalne testy, testy regresyjne.
    02 — ETLpipeline.py

    Przychód netto ze sprzedaży

    CSV zawierał duplikaty, dodatkowy nagłówek, wiersz TOTAL, różne formaty liczb i regionów oraz brakujące ceny. Pipeline weryfikuje dane, stosuje zatwierdzoną politykę i wylicza przychód dla pięciu regionów.
