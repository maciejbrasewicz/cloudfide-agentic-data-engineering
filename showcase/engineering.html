Warstwa techniczna / execution & provenance

Jak człowiek, ChatGPT i Microsoft Foundry zbudowali oraz zweryfikowali rozwiązanie.

To nie jest pokaz „czterech autonomicznych agentów”. To prawdziwy układ odpowiedzialności: człowiek podejmował decyzje, ChatGPT projektował i wprowadzał zmiany, GitHub uruchamiał testy, a trzy wyspecjalizowane agenty Microsoft Foundry audytowały wynik. Zobacz realne artefakty, wywołania narzędzi i granice dostępu.

03 / RECRUITER EXECUTION

Uruchom prawdziwy proces w Foundry.

Kontrolowane zlecenie do tego samego workflow w GitHub Actions. Portal pokazuje autentyczne etapy CI, wywołania narzędzi i otrzymane od modelu raporty. OIDC potwierdza pochodzenie zdarzeń; przeglądarka nie otrzymuje uprawnień Azure.

STATUS POŁĄCZENIASprawdzanie konfiguracji…

Maksymalnie dwa uruchomienia dziennie, jeden aktywny przebieg i przerwa między zleceniami. Tryb recenzenta nie może samodzielnie zmieniać kodu ani przyjmować decyzji modeli.

Zobacz w GitHub Actions ↗

Bezpieczne uruchomienie

GitHub workflow_dispatch, ograniczony workflow, Azure Entra OIDC, a nie klucz Azure w stronie.

Prawdziwy strumień zdarzeń

Token OIDC runnera jest kryptograficznie weryfikowany; zdarzenia zawierają tylko metadane i jawnie oznaczone, nieufne podsumowania modeli.

Kontrolowana ekspozycja

Bez argumentów narzędzi, promptów, sekretów, arbitralnych komend i możliwości automatycznego merge do main.

04 / DOWODY I KONTROLA

Kontrakty, decyzje i kod, które da się sprawdzić.

Warstwy są rozdzielone. Kod ETL jest deterministyczny, agent ma ograniczone uprawnienia, a każda nowa decyzja modelu pozostaje propozycją do akceptacji człowieka.

DataDecision / Human approval

Model proponuje. Człowiek zatwierdza.

Kontrakt DataDecision zawiera rolę, zakres, dowód, ryzyko i hash źródłowego raportu. Nowe propozycje agentów są zapisywane atomowo jako pending_human_review; sama odpowiedź LLM nigdy nie aktualizuje data_policy.json.

05 / GRANICE I KOLEJNE ETAPY

Co zostało zweryfikowane, a co wymaga dalszych uprawnień lub pracy?

Nie podmieniamy statusu planowanego rozwiązania na „działa”, dopóki CI lub autentyczny przebieg Foundry tego nie potwierdzi.
