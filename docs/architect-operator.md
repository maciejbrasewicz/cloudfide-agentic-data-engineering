# P1 Data Architect — operator runbook

The first real role in the planned autonomous delivery system. P1 cannot
write implementation code or approve policy. A successful run proves that the
architect called all seven real tools, profiled original data, covered the
recruitment task and passed deterministic evidence checks.

## One-time private specification setup

Keep the ORIGINAL CloudFide task outside this public repository.
Create a GitHub Actions repository secret named CLOUDFIDE_TASK_SPEC_B64.
Its value is the Base64 encoding of the original UTF-8 assignment Markdown.

Example: run locally in Python and paste the output into the secret editor:

    import base64
    from pathlib import Path
    task = Path("C:/private/taskvirtualcolumn.md").read_bytes()
    print(base64.b64encode(task).decode("ascii"))

Base64 is not encryption. The repository Actions secret protects the value.
Never pass the spec through workflow_dispatch inputs, GitHub Issues or PRs.
The specification must not be committed to the repository.

## Run

Open the workflow:

https://github.com/maciejbrasewicz/cloudfide-agentic-data-engineering/actions/workflows/architect-e2e.yml

Choose Run workflow, main, rebuild. This is P1 ONLY; the Engineer that
generates candidate files and the Verifier are P2-P5, not active here.

The workflow uses the pinned Foundry model deployment, Microsoft Entra OIDC
and seven limited source tools: read_spec, inspect_original_tests,
profile_source, inspect_orders, reconcile_raw_control,
inspect_approved_policy, validate_policy_proposal.

## Output artifact

Download architect-p1-evidence from the successful or stopped Actions run:

- architect_report.json: six task requirements, original CSV facts and six
  policy decisions supported by original tool evidence.
- contract_proposal.json: proposed policy and rationale; it is NOT approval.
- architect_gate.json: definitive status, calls, differences and failures.
- input_manifest.json: hashes for private spec, source CSV, original tests and
  approved policy; no original task text.

APPROVED_FOR_ENGINEERING means the concrete evidence and policy checks passed.
AWAITING_HUMAN_APPROVAL means the proposed policy changes v1 and was NOT
authorized. INCOMPLETE means an actual tool, source fact, contract or
provenance requirement failed. Only the first status exits successfully.

## Local execution with Azure credentials

    uv sync --locked --extra quality --extra foundry
    uv run --no-sync python -m agentic.architect --task-file /external/taskvirtualcolumn.md --mode rebuild --output-dir /tmp/cloudfide-architect

Run from the project checkout. The task file must be outside the repository.
The result is generated by a REAL Foundry agent, not by deterministic fixtures.
